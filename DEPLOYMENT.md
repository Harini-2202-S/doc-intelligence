# Deployment

This guide deploys Doc Intelligence as a public web application using free tiers:

| Component | Service | Purpose |
| --- | --- | --- |
| Application (API and web client) | [Render](https://render.com) web service | Runs the FastAPI app |
| Database | [Neon](https://neon.tech) PostgreSQL | Users, documents, chunks, briefs, chats |
| Vector database | [Qdrant Cloud](https://cloud.qdrant.io) | Embeddings for semantic search |
| File storage | [Cloudflare R2](https://www.cloudflare.com/developer-platform/r2/) | Encrypted uploaded files |
| Language model | [OpenAI API](https://platform.openai.com) | Embeddings, briefs and answers |

Render's free tier has no persistent disk, so the database, vectors and files must live in external
services. Any PostgreSQL provider, Qdrant server and S3-compatible store can be substituted.

## 1. PostgreSQL (Neon)

1. Create a project in Neon (PostgreSQL 16).
2. Open **Connection Details**, turn **off** "Connection pooling", and copy the connection string.
   It looks like `postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require`.
3. Keep it for `DI_DATABASE_URL`. The application converts it to the asyncpg form and enables TLS;
   migrations run automatically on every deploy.

Use the direct (non-pooled) connection: the asyncpg driver uses prepared statements, which
transaction-mode poolers do not support.

## 2. Vector database (Qdrant Cloud)

1. Create a free cluster.
2. Copy the cluster URL (for example `https://xxxx.cloud.qdrant.io:6333`) for `DI_QDRANT_LOCATION`.
3. Create an API key for `DI_QDRANT_API_KEY`.

The collection and its payload indexes are created on first start.

## 3. File storage (Cloudflare R2)

1. Create a bucket, for example `doc-intelligence-files`. Keep it private.
2. Create an R2 API token with **Object Read & Write** permission for that bucket.
3. Note the values:
   - `DI_S3_BUCKET`: the bucket name
   - `DI_S3_ENDPOINT_URL`: `https://<account-id>.r2.cloudflarestorage.com`
   - `DI_S3_ACCESS_KEY_ID` and `DI_S3_SECRET_ACCESS_KEY`: from the token

Files are encrypted with `DI_STORAGE_ENCRYPTION_KEY` before upload, so the bucket only holds
ciphertext. AWS S3 or any S3-compatible service works the same way; for AWS, leave
`DI_S3_ENDPOINT_URL` empty and set `DI_S3_REGION`.

## 4. OpenAI

1. Create an API key for the deployment (separate from any key used locally).
2. Under **Billing > Limits**, set a monthly budget. A public demo should always have a hard cap.

## 5. Generate the encryption key

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Store this value safely. Files encrypted with it cannot be read if it is lost or changed.

## 6. Render

1. Push the repository to GitHub.
2. In Render choose **New > Blueprint**, select the repository, and confirm. Render reads
   [`render.yaml`](render.yaml).
3. Enter the values marked as required:

| Variable | Value |
| --- | --- |
| `DI_DATABASE_URL` | Neon connection string (step 1) |
| `DI_QDRANT_LOCATION` | Qdrant cluster URL (step 2) |
| `DI_QDRANT_API_KEY` | Qdrant API key (step 2) |
| `DI_S3_BUCKET`, `DI_S3_ENDPOINT_URL`, `DI_S3_ACCESS_KEY_ID`, `DI_S3_SECRET_ACCESS_KEY` | R2 values (step 3) |
| `DI_OPENAI_API_KEY` | OpenAI key (step 4) |
| `DI_STORAGE_ENCRYPTION_KEY` | Key from step 5 |

`DI_JWT_SECRET` is generated by Render. The blueprint also sets production mode and the usage
limits below.

4. Deploy. The start command runs `alembic upgrade head` and then starts the server. When the
   health check at `/health` passes, the application is available at
   `https://<service-name>.onrender.com`.

## Usage limits

A public deployment spends the owner's OpenAI budget, so `render.yaml` sets conservative limits.
Adjust them in the Render dashboard.

| Variable | Default in render.yaml | Meaning |
| --- | --- | --- |
| `DI_MAX_UPLOAD_MB` | 10 | Maximum file size |
| `DI_UPLOADS_PER_HOUR` | 15 | Uploads per user per hour |
| `DI_CHAT_MESSAGES_PER_HOUR` | 40 | Questions per user per hour |
| `DI_GLOBAL_UPLOADS_PER_HOUR` | 100 | Uploads across all users per hour |
| `DI_GLOBAL_CHAT_MESSAGES_PER_HOUR` | 400 | Questions across all users per hour |
| `DI_ALLOW_REGISTRATION` | true | Set to `false` to close sign-ups |

Limits are held in memory and apply per instance; the free plan runs a single instance.

## Operational notes

- **Cold starts:** free Render services sleep after 15 minutes without traffic; the first request
  afterwards takes about a minute.
- **Interrupted jobs:** processing runs inside the web process. Jobs interrupted by a restart are
  resumed automatically on the next start.
- **Scaling:** for multiple instances, set `DI_QUEUE_BACKEND=arq` with a Redis URL and run
  `arq doc_intelligence.worker.WorkerSettings` as a background worker, and move rate limiting to a
  shared store.
- **Key rotation:** `DI_JWT_SECRET` can be changed at any time (users sign in again).
  `DI_STORAGE_ENCRYPTION_KEY` must not change while files encrypted with it exist.
- **Logs and health:** Render shows application logs; `/health` checks database connectivity.
